# 登录摘要 / Login summary

状态：implementation candidate；`sai status`、Rich登录面板和Textual概览页已有本地实现，生产部署与现场验收单独记录。

更新时间：2026-09-23 07:24:27 +08:00

用户已选定：自动显示摘要面板并立即进入Shell；主动运行 `sai tui` 查看完整工作台。
当前实现接通身份、资金/预算、本人未读摘要、访问事项，工作台保留已有作业/资源/存储入口。
金额与消息合同见 [account.overview/v1](../contracts/account-overview/v1/README.md)。

## 目的与呈现

登录时回答四件事：当前查看哪个身份、资金归属是什么、有什么影响使用、下一步去哪里。
作为[统一工作台](unified-workbench.md)的简短入口，复用控制台和 CLI 的事实与权限。
新增摘要不得删除尚无等价呈现的原有信息。现阶段保留常用命令、存储配额、GPU/CPU状态、
模板和手册入口；将来压缩版式必须保留这些信息及必要公告，不能仅保留手动查询入口。

普通登录目标为 8–12 个终端显示行；窄屏折行时优先保留身份、资金和最重要的待处理事项。
最上方说明身份与站点，真实阻断紧接其后。正常状态用普通文字，只有异常使用 WARNING/需处理。
默认中文；关键状态配简短英文，账户和命令只写一次。英文呈现遵循同一字段和排序，不重复整屏双语。
不使用闪烁、蜂鸣、巨大 ASCII 标识或仅靠颜色表达状态。

| 内容 | 默认展示 | 展开或条件展示 |
| --- | --- | --- |
| 登录上下文 | 本人、本站点、默认身份名称及 Slurm Account、实际进入的目录 | 默认设置尚未应用、目录切换失败、身份已失效 |
| 当前身份资金 | 现金余额与 SAI Credit 分列；项目范围按权限显示项目预算 | 可用授信、运行未结算估算、额度到期、现金到期应付款 |
| 使用状态 | 经确认的本站准入状态；可与作业行合并 | 提交暂停的具体原因、恢复中、本人能够执行的下一步 |
| 消息 | 本人于当前身份、当前站点的未读总数及短分类 | 至多两条重要摘要，提供同范围消息中心入口 |
| 作业 | 本人本站运行/排队数量，明确与当前资金范围的区别 | 可处理的排队原因、近期失败、受管任务待确认；不列全部作业 |
| 存储 | 当前已授权目录的剩余容量或使用/有效额度，注明采样时间 | 文件数量额度不足、配额调整未生效、目录访问异常 |
| 时间敏感事项 | 有实际影响时进入待处理区 | 本人认证/成员资格、Credit/订阅到期；相关维护窗口、待审批/邀请 |
| 导航 | 一个摘要刷新入口及同身份控制台入口 | 作业详情、资金明细、消息正文、资源目录、帮助与联系运营 |

正常时不铺陈认证有效、所有配额正常等多条“绿色结论”。消息为零可用一个短值；没有维护、
到期或审批事项时不留空栏目。运行/排队数量须来自完整聚合，截断的页面只能写“至少 N”，
不得把 `--limit 100` 的长度当总量。普通排队不当作错误，也不预测未经验证的启动时间。
配额必须显示实际生效值，目标额度和“申请已受理”不能冒充可用容量。
没有当前目录到授权工作区的确切对应时，只显示并标注工作区配额，不称其为当前目录配额。

## 身份与资金口径

“当前身份”在登录摘要中明确指登录时选中的默认工作身份，沿用现有偏好，不增加 MOTD 身份设置。
Portal 拥有业务身份/资金归属；站点已应用默认值与实际目录是独立事实。先完成已有目录选择，
再显示摘要。用户指定初始目录、目录切换失败、控制台偏好尚未同步时，展示差异，不能把两个身份的事实拼起来。
目录只在本地展示，不把任意路径发给中心，也不在客户端重新实现路径到账户的授权规则。

登录摘要是当时的快照；随后 `cd` 或显式 `--account` 会影响提交账户，不能承诺后续全部作业
记到所显示的账户。提交和 `scontrol update` 继续由已有共同账户策略处理，冲突仍给出计费提醒。

- 现金余额、SAI Credit、后付费授信、项目预算分别沿用现有定义，不能都写成“余额”。
  显示币种和 Credit 单位；Credit 的适用站点、用途与有效期由服务端解析，不假定所有 Credit 都能用于当前计算。
- 可展示服务端已核算的“计算可用额度（折合）”，但它不是现金、可提现额或作业完成保障。
  客户端不把现金、Credit 和授信直接相加，也不再扣一次运行中预留。
- 金额使用同一当前资金位置与 allowance 事实，包含原服务的运行占用/预留处理。
  消息里的历史余额或未来到期后预计余额不能当成当前余额；当前与到期后两种数值须分开。
- 现金为零但有适用 Credit，不直接报欠费；现金为负但有有效授信，不直接报无法提交。
  资金不足、成员限额、认证、站点可用性和原生调度限制是不同原因，消费既有准入/回执状态。
  无完整证据时显示“提交状态未确认”，不能只凭余额给出“可正常使用”。
- 有效组织成员可读取该组织的共享余额，写权限仍按原角色控制。项目成员的预算可见性和
  组织现金可见性分别核权，不通过登录摘要扩大到整个付款组织。隐藏金额不渲染为零。
  组织共用资金要写明“组织共享”，不能让成员误认为是自己的专属额度。
- 充值/处理应付款入口只给有权限的人；普通成员看到“联系组织管理员”。提醒的时间、阈值、
  适用范围复用现有策略，不为 MOTD 新增一套余额预警或耗尽时间预测。

## 未读消息与待处理事项

消息范围为 **本人收件箱 ∩ 当前工作身份 ∩ 当前站点**，复用消息中心的 recipient、
membership、workspace/site 筛选与 `read_at`；不读取全组织消息再客户端筛选。
本人认证或访问受限等跨身份事项独立展示，不因当前处于组织/项目身份而隐藏。
“当前身份有权限”也不代表该身份下其他人的消息属于本人。

未读是阅读状态，待处理是业务状态，两者不互相推断：

1. 持续生效的使用阻断优先，即使相关消息已读也仍显示。
2. 有明确期限且需要本人操作的事项其次，如认证将到期、资金补足、本人待审批。
3. 未读的完成通知/公告按类型和已知关联对象合并，例如“2 项配额申请已完成”，保留未读总数。
   已解决或过期的旧通知仍可在消息中心阅读，但不再当当前阻断。
4. 同一资金/任务异常已在待处理区出现，消息摘要只计数或引用，不重复正文。
   依靠已有事件类型和对象引用做有界展示去重，不建立第二个通知状态表。
5. 登录展示不标已读、不接受邀请、不确认方案，也不触发邮件或后台任务。
   读状态继续由消息中心的显式操作管理。

同屏最多三条需行动事项，未读摘要占其中最多两条，其余写“另有 N 项，进入控制台查看”。
数量必须区分原始消息数和合并后的事项数；未完整统计时不虚构 N。
只有未读数多，不使用“严重警告”。标题和摘要来自已有模板/结构化事实的确定性展示，
不运行 LLM 摘要、不下载正文附件、不原样输出 HTML、任意控制字符或未授权的文件内容。
动作链接只指向受信控制台对应身份、站点和对象；打开后重新核权。

## 示例

以下是合成数据，命令 `sai status` 是本设计拟新增入口。数字不表示任何真实账户。
默认只显示一份短摘要，完整明细通过手动刷新/控制台查看。

```text
SAI · site-a                         摘要时间 09-23 09:00
默认身份  示例课题组 / Account=org-example
当前目录  /org/org-example/alice
资金      组织共享：现金 ¥1,280.50 | SAI Credit 20,000 点
作业      本人本站：3 运行 · 2 排队
存储      当前工作区剩余 380 GiB / 有效额度 1 TiB（08:59 采样）
消息      当前身份未读 4 条：申请结果 2 · 待审批 1 · 公告 1
待处理    1 项协作申请等待您审批 → 控制台消息
详情/刷新 sai status --format table · 控制台当前身份
```

```text
SAI · site-a                         摘要时间 09-23 09:00
默认身份  示例课题组 / Account=org-example
WARNING   新提交已暂停：组织计算额度不足 → 联系组织管理员
当前目录  /org/org-example/alice
资金      组织共享：现金 ¥0.00 | 可用 SAI Credit 0 点
需处理    当前目录文件数量额度已满 → 清理文件或申请调整
消息      当前身份未读 4 条；资金提醒已在上方显示
详情/刷新 sai status --format table · 控制台当前身份
```

这里的“已暂停”和“已满”只能来自已确认的门禁回执/配额观测，不由两行余额推断。
无权查看资金时保留身份和获准事项；源故障写“资金暂不可读取”，不能显示 ¥0。

## 集成边界

静态 PAM MOTD 只保留公共欢迎/必要公告。金额和个人消息不能写入共享 `/etc/motd`、
`/run/motd.dynamic` 或 NFS 公共摘要文件；在认证后的本人交互式登录 shell 中呈现。
沿用一个 NFS 共享 profile 和 CLI 发布点，不新增挂载、MOTD daemon 或逐计算节点安装。

`sai status` 作为工作概览的只读命令，JSON 仍为机器接口，登录显式选择 `--format tui` 的Rich面板；
`--format table` 保留无UI依赖的纯文本输出。
它复用现有配置、Identity 会话、DTO 校验和领域客户端，不自动启动 TUI 或 Pilot。
`sai auth status` 继续负责认证诊断，不逐步塞入钱包和消息功能。
登录摘要替代重复认证输出，原有帮助、配额、资源状态和说明仍自动展示一次。
先切换默认目录，再查询该目录配额，最后显示身份/资金/消息面板并进入Shell。

| 事实 | 已有基础 | 本摘要需要补齐的合同 |
| --- | --- | --- |
| 身份、站点与付款归属 | 默认偏好、workspace context、payer resolver、站点应用状态 | 当前主体/身份/站点的只读上下文，区别期望值和已应用值 |
| 资金与项目预算 | 现金快照、WalletFundingPosition、allowance/预算/准入服务 | 窄金额摘要及独立资金权限；现有运行估算 DTO 不包含钱包余额 |
| 未读/待处理 | 消息中心查询和既有邀请/任务记录 | 有界 count、类型摘要、对象引用与动作；完全复用既有范围过滤 |
| 本人认证 | `GET /v1/account/cli/status` | 复用服务结果；该 recovery 路由继续无身份/站点筛选，不扩成资金入口 |
| 本人本站作业 | 授权 jobs list/detail、原生按需只读适配器 | 完整聚合或明确截断；不能从队列消失推断失败/完成 |
| 工作区存储 | `storage quota-summary` 的采样/有效/目标额度合同 | 复用字段和独立存储权限；当前配额读不冒称原生实时查询 |

建议在现有 Portal 正常授权 CLI 读边界加入一个小的工作概览投影，聚合中心拥有的
上下文、获准资金和消息摘要；不新建聚合服务、消息库、余额公式或全节点采集器。
具体路径/schema 和独立 OAuth 权限随跨仓实现冻结。现有恢复路由的宽读取条件不能传染到
资金或消息；已有 job/estimate capability 也不因此获得钱包权限。

动态作业/资源事实继续按[原生按需读取设计](site-local-read-plane.md)走获准的窄读取器；
控制台已有资金、消息、配额采样保留其事实源和观测时间。中心概览不临时启动全群 SSH、
`sacct` 扫描或递归目录扫描。登录不得触发资金初始化、风险重新评估或采样写入。
现有消息 count 实现仍需核实大收件箱的有界成本，优化应在原消息 owner 内完成。

只在首次本人交互式登录展示一次；root、非交互 SSH/SCP/SFTP、嵌套 shell 和作业跳过。
按现有刷新流程串行处理凭据；全摘要共用时间预算，不串联多个完整的 5 秒超时。
性能验收目标为已有有效会话时 P95 额外耗时不超过 500 ms、总等待硬上限 2 秒，
这是待测目标，不是当前实测承诺。超时后一次性输出已确认的部分及简短缺失状态，立刻返回 shell。
不在提示符后异步补打印、不无限重试、不自动打开设备登录；无会话时只给 `sai auth login` 指引。

新存储/资金/消息权限需显式获得，不能凭 SSH 成功扩权或后台自动扩大 OAuth scope。
每部分携带实际观察时间与来源；失败/无权/未知/过期/真正为零须区分。
复用原凭据缓存，不增加持久 MOTD 快照或每用户“上次登录已处理”数据库。
不把展示过的状态当作下一次调用的授权凭证。

## 实施与验收

优先一次交付身份、获准资金、未读摘要和必要的访问事项，并保留原有登录信息。
作业/配额行接入已具备相应权限、范围和精度的既有读取；缺合同的项目不以占位零值上线。
保留原生 Last login 等安全事实，不把系统维护提示、全部GPU/CPU表、全量别名和长期教程
强塞进个人摘要；相关维护只显示真实作用范围及时间。空闲资源、价格表和完整任务历史留在工作台。

必须验证：

- 个人、组织成员/管理员、项目成员的金额和消息可见性；无成员/过期/撤权、跨站点及身份切换隔离。
- 现金零但 Credit 有效、现金负但授信允许、项目预算受限、Credit 即将到期、预留不重复扣减。
- 本人全局访问问题与当前身份消息并存；旧消息已恢复；未读数和条目同范围；登录不改 `read_at`。
- 原生默认尚未同步、目录不可达/显式目录、共享目录配额与 Home 配额不同。
- 千条未读、截断作业列表、消息中控制字符、无token/缺scope/服务超时、不同事实观测时间。
- 80/40列、无ANSI终端、中文/英文；普通/嵌套/非交互登录、SCP/SFTP、计算作业均符合输出边界。
- 实际登录各受管入口输出一致，全部来自同一共享版本；保留可原子恢复的profile与客户端版本。

用真实用户任务评估“能否在五秒内指出当前Account、资金状态和下一件需处理的事”，
并测登录新增延迟。字段正确、终端可见和用户理解是三个不同验收结果。
