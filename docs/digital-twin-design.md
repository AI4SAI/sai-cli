本文补充[统一工作台](unified-workbench.md)，保存用户已确认的方向和具体设计，避免以后只剩一张机房展示图。当前不安装建模工具、不生成真实资产模型、不部署采集或控制服务。

## 当前事实与第一段设备关联

当前作业分配链已提供按授权裁剪的节点及 CPU/内存分配，并复用同一原生
Slurm JSON 的 `gres_detail`，经节点原始顺序核对后给出 GRES 名称、类型、分配
数量及可空的 Slurm 本地索引。`jobs.allocation/v2` 是三端配对迁移，沿用原
operation 和查询；不新增全站节点读取或资产状态副本。

这些索引仅表示调度资源。MIG 也可能显示为 `gpu`，MPS/shard 的数量是各自单位；
不能画成物理卡、CUDA/NVML 编号、UUID、插槽或利用率。缺失、未知及证据错位保持
null，不能以请求量、whole-node 标志或分区平均规格补齐。格式根据固定 Slurm
25.05 源码核查。2026-09-29 已额外验证一个真实 Slurm 26.05.1 / v0.0.45
typed GPU IDX 样本：既有低权限服务用户可读取，当前 parser 的单节点绑定与
资源索引一致。此样本不覆盖数组、多节点、shared/MIG 或物理设备映射；gateway
仍未运行，不能据此宣布部署后的授权读取链就绪。

本地运维资料已有从布局表白名单提取的机柜/U 位历史快照，以及独立的主机命名
和拓扑记录；它们缺少当前复核时间、资产更换代次及维护中的 GPU UUID/槽位映射。
生成器布局坐标是示意值，不能标成实测。后续从现 owner 的受控快照发布，补齐
来源、修订和明确站点/集群/节点绑定。原始资产表可能含运维凭据，应只导入必要
字段的投影，不能直接作为浏览器资源或提交进客户端仓库。

## 1. 已确定的方向

- 数字孪生由“实体、关系、时变观测、工作负载关联、来源与质量”构成，3D 是其中一个视图。
- 动态观测优先在站点从 Slurm、Lustre 和设备原生接口按需取得；孪生不是复制这些系统的全量状态库。
- 普通用户先看授权资源容量和自己可见任务的硬件落点；管理员按独立授权看设备、网络、故障详情。
- 从资产清单生成参数化机房和服务器模型；缺少实际布局时明确使用示意布局。
- TUI、WebUI、Pilot/Agent 读取同一组孪生事实；Agent 无需理解或截取 3D 画面。
- 当前主线是统一产品与数据合同；3D 建模、美术、模型工具和高级推演以后实施。
- 当前开发环境没有 3D 建模工具。确有必要时可在合适的独立环境使用 Blender 等软件；这是工具选择空间，不是对任意生产节点安装或变更的授权。

## 2. 孪生的四层

| 层 | 内容 | 更新方式 |
| --- | --- | --- |
| 实体与空间 | 站点、房间、机柜、U 位、服务器、GPU/设备、端口；物理/示意坐标 | 经过校验的清单修订与版本化模型 |
| 连接与能力 | 包含关系、网络/设备连接、分区成员、规格、可用软件/约束 | 有来源的拓扑或目录修订 |
| 观测与分配 | 调度状态、实际分配、GPU/CPU/内存/网络/温度等指标 | 有界采样与状态转换，逐来源标时 |
| 任务与业务 | ComputeRun/原生作业/尝试、授权上下文、运行估算、结果引用 | 从各 owner 的现有事实投影 |

物理事实来自设备清单和原生观测；Portal 控制对用户发布的视图。3D 文件不能成为新的资产数据库。先完成只读状态同步与任务关联；预测、故障推演、控制闭环分别立项，不能从“孪生”名称推出远程控制权限。

默认装配方式是版本化静态模型加按需原生观测，用稳定实体/代次引用即时关联。新建页面不要求先部署全量 collector、事件总线、图数据库或时序数据库。已有观测设施可以复用；仅当明确的历史/趋势功能需要时，才保存相应范围和留存窗口的数据。原生采集、短期缓存和历史记录必须可区分。

## 3. 实体、时间和关系

`asset_ref` 表示持续受管的对象，`incarnation_ref` 表示当前设备实例，`placement_ref` 表示安装位置。设备被替换时保留位置历史，但创建新设备实例；移动服务器更新时段关系，不按显示名把新旧遥测拼接。

机柜、服务器、GPU、网络端口均有稳定引用和类型。主机名、序列号、GPU UUID、PCI 地址、MIG/虚拟设备标识只作为受控原生映射；普通用户使用安全标签，Agent 默认也不取得运维标识。物理 GPU、分片和虚拟设备保持不同实体，显存和容量不得重复求和。

拓扑修订包含 `revision`、`valid_from/to`、记录时间、导入来源与校验结果。关系包括 contains、installed_at、connected_to 和 member_of。机房/机柜树与 Slurm 分区是两种关系：同一节点可属于多个分区，不能因此复制硬件或重复统计总量。

`allocated_to` 属于独立的时变分配层，使用 `allocation_revision` 引用对应 `topology_revision`。调度分配变化不重发整份静态资产拓扑；历史查询按有效时段关联两层。

工作负载关系使用 `job_ref + execution_attempt_ref + allocation_ref`，记录有效时间和已分配设备。Slurm 只提供 GPU 数量时只画节点级数量占用；没有可靠设备索引映射时不随机点亮具体 GPU。可从管理工具读取到 GPU UUID 也不自动证明某任务拥有该设备。

观测包含实体/实例、指标键、值/单位、观测时间、窗口、质量与覆盖率。累计计数器标记重置；跨设备代次不能求速率。每个来源记录时钟偏差或时间可信度，延迟数据不能倒退当前状态。

## 4. 必须区分的状态

| 事实 | 含义 | 不能替代 |
| --- | --- | --- |
| 装机容量 | 实际资产规格 | 可供用户使用的额度 |
| 调度可用 | 分区状态与资源当前可分配情况 | 对该用户立即启动的承诺 |
| 已分配比例 | 调度器分配量/明确容量分母 | 实际 GPU 计算利用率 |
| 实际利用率 | 有单位、时间窗和来源的测量 | 程序效率、科学结果质量 |
| 健康状态 | 已观测诊断与故障事实 | 没有报警就认定健康 |
| 运行估算 | 非最终费用、价格版本与不确定性 | 已扣费或最终结算 |
| 推演结果 | 指定假设与模型版本下的预测 | 实际拓扑或调度结果 |

单卡利用率属于物理设备观测；共享 GPU、MIG、MPS 或复用设备没有进程级归因证据时，不能标为“本任务利用率”。只返回当前角色被允许的层级；必要时仅提供任务可归因摘要。未采集、映射缺失、过期和真实零值分别显示。

## 5. 从清单生成参数化模型

导入字段至少包括实体引用/类型、实例、父对象、机柜高度/U 位、服务器尺寸/朝向、设备槽位、规格型号、有效时间、来源与可见性分类。真实房间尺寸、机柜坐标和网络连接分别可选；未提供的内容不得伪造为现场事实。

导入校验检查引用唯一、父子无环、U 位/几何不冲突、单位一致、端口关系有效、修订时段明确、移除对象有生命周期语义。修订先校验再原子发布，失败保留上一有效版本并显示来源错误；不把半份清单当完整机房。

参数化类型库从少量可复用模板开始：机柜、不同 U 高的服务器、板卡/GPU、交换设备。型号可决定外形和槽位，资产实例只绑定模板参数与安全标识，不为每台设备复制模型。未知型号显示通用轮廓及“通用外观”。

场景提供 `layout_kind=measured|schematic` 与 `model_fidelity=generic|model_family|measured`。只有有依据的尺寸和坐标显示物理比例尺；示意布局不用于距离、布线长度或风道分析。面板始终可辨别当前模型精度。

## 6. 3D 场景与交互构思

**机房层**展示机柜分布与选定指标的概览；**机柜层**展示 U 位和服务器占用；**服务器层**展示机箱/板卡槽位；**设备层**展示具体 GPU 或共享设备分片。逐层进入，避免初屏绘制所有线缆和器件。

| 操作 | 反馈与联动 |
| --- | --- |
| 悬停 | 简短安全标签、主指标和观测时间；触屏可点击取得同内容 |
| 单击实体 | 选择固定，打开语义详情，联动可见任务列表 |
| 从任务定位 | 高亮有确证分配的设备；相机平缓聚焦，可取消动画 |
| 双击/明确进入 | 下钻一级；面包屑和返回保留筛选与时间 |
| 切换指标层 | 已分配、利用率、显存、健康等单一主色层，图例注明单位与范围 |
| 切换时间 | 共同时间游标驱动拓扑与观测；无历史数据时禁用并说明 |
| 交给 Pilot | 附加实体/尝试/时间窗引用，预览将带入的范围 |
| 切为表格/2D | 同实体、筛选和选择，不重置任务上下文 |

默认以空间形状表达包含关系、颜色表达当前指标、描边/标记表达选择，不能同时用同一颜色表达所有权、健康和利用率。未知用中性外观与文字；无权显示的对象在服务器投影中排除，不能只靠隐藏 mesh。

网络连线默认关闭，按选中实体及关系类型局部展开。普通用户只看经允许的逻辑通信能力/相关连接，不能从空机位、隐藏链接、数量差分推断其他租户或敏感设备布局。管理员取得详细拓扑也需要单独 operation。

服务器拆解采用可控分层/爆炸视图，不做自动循环动画；仅对有型号结构依据的模板显示精确槽位。前后视角、恢复视角、缩放与下钻都有键盘替代。相机方位是本地视图状态，不写入业务权威。

## 7. 渲染架构与工具边界

划分为事实适配、场景实体映射、几何模板/资产目录、渲染运行时和交互选择五部分。语义状态与渲染引擎解耦，同一选择模型驱动 DOM 详情、2D 树、TUI 和 Agent context。

优先在现有 Web 技术栈中用参数化几何与实例化渲染完成第一版。复用公开首页已验证的生命周期、降级和几何经验，但不复制整页滚动叙事、硬编码规模或数据。

Blender 只在参数化基础不能满足服务器外观、结构或网格优化时使用。届时选择独立开发/渲染环境，以通用清单生成 `.blend` 源与 glTF/GLB 展示资产，保留生成脚本、单位、坐标约定、模板版本和许可。运行时不依赖 Blender，不上传私有清单到外部模型服务。

3D 资产与拓扑都经过发布授权；GLB 节点名、隐藏 mesh、extras、纹理元数据不能藏有完整站点、地址或序列号。浏览器只下载当前用户获准的模板和实例投影，不先下载全站再前端隐藏。

## 8. 性能、可访问性与真实感

按机房/机柜分块、视口裁剪、实例化和层次细节加载；telemetry 更新属性，不每轮重建几何。暂停隐藏标签页的渲染与高频订阅，退出释放 GPU/纹理/事件监听。后台任务继续由服务端运行，不依赖画布生命周期。

首版验收目标：普通浏览器进入工作台先显示可操作 DOM；场景异步加载；千节点合成场景聚合交互至少 30fps、选择反馈目标 100ms 内。记录设备、浏览器、分辨率、模型数量与实测，不把目标数字写成已达性能。

低端设备、WebGL 不可用、远程桌面、减少动画或屏幕阅读器下提供完整列表/2D 视图。支持键盘焦点、中文/英文标签、非颜色状态与明暗皮肤。真实感首先来自可信几何关系、状态和时间，不靠高面数、发光或伪实时动画。

## 9. 历史、推演和操作边界

历史回放必须使用对应有效时段的资产、拓扑、尝试和观测；不能在今天的硬件上画昨天的分配而不注明关系变更。历史能力按已保留的来源窗口公开，清单与观测缺失时显示缺口，不进行默认插值。

预测/what-if 以后再接：例如改变 GPU 数量、比较分区、计划维护的影响。输入假设、模型版本、适用范围、置信度、校准证据与预测时间必须可读，预测覆盖层和实测层分离。先用确定性容量约束比较，不假装具备尚无验证的排队或性能预测器。

任何“调整资源”“迁移”“取消”都只产生既有执行系统可评审的意图；孪生不直接写 Slurm/BMC/存储，不创建第二调度器。Agent 不因能读管理员视图而自动获得这些动作。

## 10. 最小真实闭环及验收

先用一组授权样本贯通：清单中的一台服务器/一块设备 → 当前实例与槽位 → 一次作业尝试的真实分配 → 一个已采集指标 → 同一任务的 Web/TUI/Agent 引用。没有设备级映射时，以节点级分配验收并明确缺口，不能拿随机 GPU 填齐演示。

必须覆盖：清单撤回、设备更换、节点改名/移动、重排队与 Job ID 复用、GPU 分片、多分区去重、共享设备归因不足、时间错位、telemetry 中断、授权撤销、模型加载失败和多用户缓存隔离。既验证“显示了正确对象”，也验证“没有显示不该显示的对象”。

在三端数据闭环通过后再验收几何、美术、相机、性能与可访问性，最终另做现场核验。合成清单、mock 指标和离线场景只能证明交互与协议，不能标为真实机房数字孪生上线。
